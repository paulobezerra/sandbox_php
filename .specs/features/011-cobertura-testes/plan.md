# PLAN — Behavioral coverage for PHP and frontend code

**Feature:** [feature.md](feature.md) · **Spec:** [spec.md](spec.md) · **Date:** 2026-10-21 · **Status:** open

**User validation to start Code:** Paulo Bezerra approved this revised Plan by stating “aprovar” on 2026-10-21.

## Delivery strategy

Deliver separate PHP and frontend coverage reports and gates, then document test selection and practice and wire the gates into their independent CI jobs. Keep PHPUnit, Vitest, and GitHub Actions as the preferred stack. First verify their supported coverage/report capabilities and maintained extensions; adapt the existing PHP checker or add only small project glue if native tooling cannot enforce a stated threshold, recording the specific gap and compatibility/support evidence in Code. Keep coverage dependencies development-only. Do not change production behavior or refactor application code solely to increase percentages. Keep backend and frontend suites service-free as required by the Spec.

## Risks and final verification

PHP must report Xdebug branch data in addition to Clover line counts and must include uncovered in-scope files without counting tests, dependencies, or generated files. Frontend coverage must include unimported files and keep its provider development-only. Each of the four limits (PHP lines 95%, PHP branches 85%, frontend lines 95%, frontend branches 85%) must independently fail CI when missed. Verify that each coverage job is service-free and its failure blocks the intended downstream checks. There are no application, HTTP contract, database, migration, deployment-runtime, browser, or end-to-end testing changes in this feature.
