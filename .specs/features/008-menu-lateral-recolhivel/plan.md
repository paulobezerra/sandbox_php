## Delivery strategy

Deliver the PHP/Vite development and production asset path first, migrate the existing SPA into the new source/build structure, implement the collapsible shell interaction, align user-facing guidance with the actual frontend workflow, and finish with integrated browser tests. The PHP application remains responsible for the shell and API in both environments. No database, API, route, or authorization changes are planned. The Spec's explicit approval of Vite, Vue SFCs, Tailwind, shadcn-vue, and bundled Lucide resolves its documented divergence from the original Feature constraint.

**Parallel execution guidance:** the user authorized subagents for this feature. T008-04 is contractually independent of the implementation tasks because the Spec fixes the commands and deployment behavior; its README, translation, and asset work may proceed in parallel with T008-01 through T008-03. Its Home component markup overlaps the T008-02 migration, so assign that file to one agent or integrate the edits sequentially. T008-01 must be integrated before T008-02 can pass its build gate, and T008-02 must be integrated before T008-03 can pass its shell behavior gate. T008-05 follows integration of all four tasks and checks that the delivered implementation matches the documentation. Delegate only bounded work with clear file ownership; the lead Code agent resolves integration and records task completion after the applicable gates pass.

## Risks and final verification

The main integration risk is keeping development-only Vite/HMR permissions out of production CSP while preserving same-origin API requests and serving manifest-resolved assets in production. Browser verification must cover development and production template paths, including the missing-manifest failure. The SFC migration spans every route and shared API behavior, so route, authentication, CSRF, safe Markdown, and loading/error behavior need characterization and integrated browser coverage. No persistence or API contract changes are expected.
