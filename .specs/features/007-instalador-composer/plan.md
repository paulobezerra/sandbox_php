## Delivery strategy

First make the repository a clean Composer project package and prove its distribution and installation behavior using an isolated local fixture. Then update the README as the complete first-use and operations guide, followed by the bilingual Home summary and its locally served technology marks. The documentation and Home tasks can build on the package command and exclusions established by the first task. No application, HTTP, database schema, or deployment automation behavior changes.

## Risks and final verification

The principal integration risk is whether the actual Composer distribution source honors archive exclusions, especially for GitHub-hosted package archives. T007-01 must verify the exact source used by `create-project`; a locally generated Composer archive alone is insufficient evidence if the documented public source uses a different dist mechanism. Packagist registration/publication remains outside this implementation and must be completed before the concise public command works against Packagist.

The Home changes span both locale catalogs, browser rendering, and static SVG assets. At feature completion, verify catalog parity, both locale renderings, locally served marks, link destinations, and the complete package archive/install contract. Do not run database migrations or deployment commands as part of these checks.
